# Clash Party 覆写规则

用于 Clash Party 的 JavaScript 配置覆写，为节点、地区和各服务策略组提供「全局直连」选项，并保留自动选优、故障转移、轮询负载均衡及散列负载均衡功能。

## 导入使用

在 Clash Party 的「覆写」页面导入以下原始文件链接，再将该覆写应用到所用订阅：

```text
https://raw.githubusercontent.com/nodesire7/Gamepic/main/clash-party-rules/override.js
```

也可以打开 [override.js](./override.js)，将全部内容粘贴到 JavaScript 覆写编辑器中。用这份脚本替换旧版同用途覆写，保存后应用配置。

脚本支持普通节点列表、`proxy-providers`，以及两者混合的订阅配置。

## 策略组行为

- 除「全局直连」自身外，所有可见选择组均提供该选项；「全局直连」自身只包含 `DIRECT`。
- 自动选优、故障转移、负载均衡和地区组保留原名称。可见组用于手动切换，隐藏的自动核心继续运行对应算法。
- 自动核心只使用代理节点，不将直连加入自动候选。空地区或没有可用节点时，不会自动回退为直连；需要直连时可在可见组中主动选择。
- 保留自定义分流规则，并调整服务规则顺序，例如让 YouTube 规则先于 Google 总规则生效。

## 客户端测速设置

在 Clash Party 的延迟测试设置中填写：

| 设置 | 值 |
| --- | --- |
| 测速地址 | `http://www.msftconnecttest.com/connecttest.txt` |
| 超时时间 | `5000 ms` |

可见选择组和直连使用微软检测地址，预期返回 `200`；隐藏自动核心使用 `https://www.gstatic.com/generate_204`，预期返回 `204`，用于检查代理的海外访问能力。

测速显示的是到检测地址的连通延迟，不是下载带宽。订阅已有的自定义健康检查地址及显式关闭设置会保留，自定义地址不会被强制要求返回 `204`。
